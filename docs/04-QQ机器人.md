# QQ 机器人（可选）

装上之后，在班级群里 @ 它说一句话，网页里的收件箱就多一条消息，确认后变成 DDL 或长任务。

**前提**：必须先完成 [部署到云端](02-部署到云端.md)。机器人是往云库写数据的，没有云库就没有落点。

---

## 它为什么是「一份文本」而不是一个程序

`skills/campus-inbox/SKILL.md` 是给 AI 的**行为规范**：收到消息后怎么判断、写哪张表、哪些字段不许瞎填。

所以「安装」就是把文件放对位置，没有编译、没有依赖、没有进程要常驻。

---

## 第 1 步 · 装技能

把 `skills/campus-inbox/SKILL.md` 复制到：

```
Windows:  C:\Users\<你的用户名>\.workbuddy\skills\campus-inbox\SKILL.md
macOS:    ~/.workbuddy/skills/campus-inbox/SKILL.md
```

放在这里对所有工作目录生效。也可以放在某个工作目录下的 `.workbuddy/skills/`，但那样只在该目录生效。

**验收**：在 WorkBuddy 里说「列出可用技能」，能看到 `campus-inbox`。

---

## 第 2 步 · 改两个值（这一步不做，数据会写进别人的库）

打开 `SKILL.md`，把它里面的占位符换成你自己的：

| 找什么 | 换成 |
|---|---|
| `wbapp_你的应用ID` | 你第 1 步创建的应用 ID，形如 `wbapp_xxxxxxxxxxxxxxxx` |
| `你的owner_id` | 你自己账号的 `owner_id` |

`owner_id` 出现在**好几处**（写库铁律一处 + 六类查询的 SQL 各一处），用全文替换一次改完，别只改第一处。

**怎么拿到自己的 `owner_id`**：

1. 打开你部署好的网页，用手机号登录
2. 手动加一门课（内容随意，之后删掉）
3. 在 WorkBuddy 里说：`执行 select distinct owner_id from courses`
4. 返回的那串就是，形如 `wu:xxxxxxxxxxxxxxxxxxxx`

**自查**：改完在 `SKILL.md` 里搜 `wbapp_你的应用ID` 和 `你的owner_id`，**都应该是 0 命中**（说明全换掉了）。

> 这一步出错的表现很隐蔽：机器人会回话、看起来一切正常，但数据全进了上一个填这个技能的人账号里。
> 所以每次装完都做一次自查。

---

## 第 3 步 · 绑定 QQ 机器人

1. 打开 <https://q.qq.com>，用你的 QQ 号注册开发者（个人开发者可申请，需实名，可能要等审核）
2. 创建机器人应用，拿到 **AppID** 和 **AppSecret**
3. WorkBuddy 客户端 → 助理设置 → 渠道 / 连接器 → QQ → 填进去
4. 把这个机器人拉进你要用的群

**卡点预告**：如果平台要求企业资质或审核不通过，这条路就走不通。
那就只用网页 + 手动录入，机器人这一环放弃，不影响其他功能。

**验收**：在群里 @ 机器人 发一句「你好」，它回话了。

---

## 它是怎么被叫起来的

不是「一直在监听」，而是：

```
QQ 连接器收到消息
  → 开一个 agent 会话
  → agent 发现 campus-inbox 技能匹配
  → 按技能里的规范调用数据库工具
```

所以三件事必须同时成立，缺一条它就不动：

1. 连接器在线（客户端开着，QQ 渠道显示已连接）
2. 技能装对了，两个值是你自己的
3. 你的云应用存在，且 `applicationId` 填的是它

---

## 它能干什么

在群里 @ 它，或者说私聊：

| 你说 | 它做 |
|---|---|
| 「下周三前交操作系统实验报告三，纸质交到 A107」 | 写进收件箱 → 变成一条 DDL |
| 「明天有什么课」 | 只读查询，直接回答，不写库 |
| 「这周还要交什么」 | 同上 |
| 「我是不是有东西落后了」 | 同上，会指出逾期的和落后的阶段 |
| 发截图 / 语音 / 合并转发的聊天记录 | 都能读，先落收件箱 |

它**不能**：改别人的数据、自己编截止日期、在你没确认时删东西。

拿不准的事它会挂在 `待处理` 等你看，不会硬塞进 DDL 表。

---

## 四个已知的失灵方式

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 群里怎么 @ 都不回 | 「获取群内全部消息」被打开了，这个开关会把机器人彻底搞哑 | 关掉它，群里老老实实 @ |
| 用着用着显示「该机器人的『灵魂』不在线」 | QQ 长连接是 WebSocket，网络抖动后可能彻底不再重试 | 助理设置里断开重连，或重启客户端 |
| 消息进了收件箱，但 DDL 页没有 | 技能把这条判成「不明确」，挂在待处理等确认 | 看收件箱那条的备注，补一句明确信息再发 |
| 合并转发的聊天记录时间不对 | 转发卡片不带发送时刻，里面的相对日期推不出来 | 会标「待确认」，手动补一下 |

第二条要特别说明：这不是 bug。长连接僵死后必须人工踢一脚，重启客户端最快。

---

## 一个必须接受的事实

机器人跑在**你自己的电脑上**，不是云端。所以：

- 电脑关机 → 机器人不在线 → 群里 @ 它没反应
- 电脑睡眠唤醒后会自动重连

想 7×24 在线，需要一台常开的机器。对课程项目来说，用到的时候开一下客户端就够了。
