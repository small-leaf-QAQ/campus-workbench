# 二次开发

这项目只有一个文件，改起来其实很简单——但有几个坑踩过之后才明白。这一页先说结构，再说坑。

---

## 结构：一个文件，按节分开

`campus-workbench.html` 从上到下大致是：

| 位置 | 内容 | 搜索关键词 |
|---|---|---|
| 文件头 | `<style>` 全部 CSS | `:root` 变量在最前面 |
| 中部 | 页面骨架（登录墙、侧栏、六个面板） | `id="authGate"` / `id="pane-` |
| 后部 | 一大段 `<script>`，按功能分节 | 见下表 |

`<script>` 里的分节顺序（每节都有 `/* ===== 标题 ===== */` 形式的注释）：

```
云服务配置       CLOUD_CFG / CLOUD_TABLES         ← 部署时改这里
配置常量         DB_ID_* / SEM_WEEKS / DAYS / SLOTS
数据源           local / cloud 两套实现的同一组签名
工具层           esc / parseDate / dateProp / clampWeek
状态             state 对象（唯一数据源）
课表             周视图、滚轮、日视图、截图导入
DDL              四栏、导入、逾期计算
长任务           阶段链推导、方案生成
收件箱           群消息、转任务
邮件提醒         设置、预览
AI 调用          模型选择、提示词
登录             登录墙、OTP、微信回跳
初始化           init()
```

**改之前先搜关键词，别靠数行号**——行号每次改都会变。

## 常见改法

### 改配色

所有颜色都在 CSS 最前面的 `:root` 里：

```css
:root{
  --brand: #d8402f;      /* 主色，红色方块、按钮、强调 */
  --bg: #f7f6f3;         /* 页面底色 */
  --ink: #1a1a1a;        /* 正文 */
  ...
}
```

改 `--brand` 一处，主色相关的全变。个别地方有硬编码的语义色（逾期红、今天截止的金棕、课程绿），
分散在 `.tag-*` 类里，需要单独改。

> **改完记得同步邮件**：`tools/daily_mail.js` 顶部的 `const C = {...}` 是另一份色板。
> 只改页面不改脚本，收到的邮件还是旧样式。

### 改文案

界面文案几乎都在渲染函数里的中文字符串。搜索你要改的那句话就行。

注意几个**不能改**的地方：

- `CLOUD_TABLES` 里的中文字段名 → 对应数据库列，改了就读不到数据
- `LOCAL_SELECT_OPTS` 里的枚举值 → 改了会和库里的历史数据不匹配
- 数据源名称（`cloud` / `local` / `none`）→ 大量逻辑判断依赖它

### 加一个字段

三处一起改，缺一处就出问题：

1. **数据库**：`deploy/schema.sql` 加列
   ```sql
   alter table public.courses add column if not exists credits text default '';
   ```
2. **映射**：页面里 `CLOUD_TABLES[DB_ID_COURSE].fields` 加一行
   ```js
   ['学分', 'credits']
   ```
3. **界面**：表单里加输入框、卡片里加显示

只改 1 不改 2：页面读不到。只改 2 不改 1：写入报列不存在。

### 改页面结构

六个面板各自是一个 `<section id="pane-xxx">`，切换靠侧栏 `#nav` 里的按钮。
加一个页面要动三处：侧栏按钮、`<section>`、`switchPane()` 里的分支。

手机上底部导航只有六格，已经排满了。再加页面要么合并，要么换成抽屉入口。

## 四个坑（都是踩过的）

### 1. JS 字符串里的相邻闭合标签会被误判

写 `'</b><i>'` 这样的字符串时，某些静态检查工具会把 `</b>` 当成真的 HTML 标签闭合，导致误报。

本项目的做法是在函数开头定义：

```js
var C = '<' + '/';
```

然后统一写 `C + 'b>'`、`C + 'div>'`。看起来丑，但能过检查。

### 2. CSS 顺序：媒体查询写在前面会被覆盖

```css
/* 错：默认规则写在媒体查询后面，同优先级下后者赢 */
@media (max-width: 640px){ .btn{ padding: 4px } }
.btn{ padding: 12px }
```

手机端覆盖规则必须**单独写一个 `@media`，放在默认规则之后**。

### 3. 时间不要用 `toISOString()`

页面所有日期解析只认字面值，不做时区换算。

```js
toISOString()          // ✗ 会差 8 小时
toLocalYMD(date)       // ✓ 项目自己的本地日期串
```

### 4. 注释里别写半角括号

某些检查工具剥离注释的实现是逐字符近似匹配，注释里的 `(` `)` 会干扰判断。
用全角括号，或者用 `①②③` 编号。

## 改完怎么验

项目没有跑 `npm test` 这种东西（没有构建，也就没有测试框架）。手动验这几条就够：

| 检查 | 期望 |
|---|---|
| 双击 `index.html` | 进主界面，不是登录墙，不是白屏 |
| 六个页签都能点开 | 每个都有内容，不报错 |
| 加一条课程 → 刷新 | 还在 |
| 课表翻周滚轮 | 有课的周底下有小点，当前周居中 |
| 手机宽度（F12 设备模拟 390px） | 课表变成一天一屏，无横向滚动 |
| 控制台 | 没有红色报错 |

改了邮件样式，还要真发一封看看：`node tools/daily_mail.js --data data.json --send`。

## 发布

改完 `campus-workbench.html` 后：

```bash
# 生成交付版（清空云配置 + 去敏 + 打 zip）
python tools/build_release.py
```

它会输出到 `dist/campus-workbench/`，并打一个 zip。

**为什么交付版要清空配置**：别人拿到你的文件，如果不小心用了你的 `publishableKey`，
数据会写进你的库。清空之后他们打开就是演示模式，必须自己填才连云端。

你自己部署的那份（根目录的 `campus-workbench.html`）保留配置，不受影响。

## 想加功能的话

几个已经想清楚但没做的方向，留给你：

- **成绩/学分统计**：`courses` 加 `credits` 和 `score` 两列就能算加权平均
- **节次时间表可配**：现在的上课时间写在常量里，不同学校不一样
- **iCal 导出**：把课表和 DDL 导成 `.ics`，塞进手机日历
- **多学期**：现在学期锚点只有一个，跨学期要清库
- **提醒改推送**：邮件之外可以加 Server 酱、企业微信之类

加之前建议先读一遍对应模块的注释——每个模块开头都写了「为什么这么设计」，
很多看起来多余的处理是为躲某个具体问题。
