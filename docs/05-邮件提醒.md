# 每日邮件提醒（可选）

每天早上把「今天有什么课、什么要交、大作业该推进到哪」发到邮箱。

**不做这一步不影响任何页面功能**，只是收不到信。

---

## 它由三块拼起来

| 块 | 在哪 | 谁负责 |
|---|---|---|
| 取数 | WorkBuddy 里的**定时任务** | 每天到点触发，查表，写一个 `data.json` |
| 排版 | `tools/daily_mail.js` | 把 `data.json` 渲染成 HTML 邮件 |
| 发信 | 你的 QQ 邮箱 SMTP | 需要**你自己的**授权码 |

缺任何一块都发不出去，而且失败是**静默的**——定时任务在后台跑，不会弹窗告诉你。

---

## 第 1 步 · 拿一个 QQ 邮箱授权码

注意是**授权码**，不是 QQ 密码：

1. 打开 QQ 邮箱网页版 → 设置 → 账号
2. 找到「POP3/IMAP/SMTP 服务」，开启 SMTP
3. 按提示生成授权码，复制下来（只显示一次）

---

## 第 2 步 · 存成环境变量

脚本读这两个名字：

```bash
QQ_EMAIL_ACCOUNT=你的QQ邮箱@qq.com
QQ_EMAIL_AUTH_CODE=上一步生成的授权码
```

Windows（PowerShell，永久生效）：

```powershell
[Environment]::SetEnvironmentVariable('QQ_EMAIL_ACCOUNT','你的QQ邮箱@qq.com','User')
[Environment]::SetEnvironmentVariable('QQ_EMAIL_AUTH_CODE','授权码','User')
```

macOS / Linux：写进 `~/.zshrc` 或 `~/.bashrc`。

设置完要**重开终端**（或重启客户端）才生效。

> 也可以不用环境变量：把 `{"account":"...","authCode":"..."}` 存成一个凭证文件，
> 脚本会问你要路径。具体看 `tools/daily_mail.js` 顶部的说明。
> **别把授权码提交到 git 里。**

---

## 第 3 步 · 在网页里填设置

打开「邮件提醒」页：

- **提醒邮箱**：收信地址（可以和发件邮箱不同）
- **推送时间**：24 小时制，如 `07:30`
- **每日汇总**：总开关，关掉整封不发
- **截止倒计时**：关掉后只列今天到期的
- **长任务节点提醒**：关掉后长任务那一块不出现
- **提前提醒天数**：提前几天开始提醒 DDL

三个开关和天数**脚本真的会读**，改设置不用改代码。

> 网页上那个邮箱只是**收件人**，和发件账号是两件事。发件人永远是环境变量里那个 QQ 邮箱。

---

## 第 4 步 · 建定时任务

在 WorkBuddy 里说：

> 每天早上 7:30 执行一次：用 `workbuddy_cloudservice_db_exec_sql` 查我的
> courses / ddl_tasks / plan_stages / remind_settings（applicationId 用 `wbapp_你的ID`，owner_id 用我的），
> 把结果写成 `data.json`，然后运行 `node tools/daily_mail.js --data data.json --send`。
> 如果 `remind_settings.last_push` 已经是今天，就跳过。

`data.json` 的结构写在 `daily_mail.js` 的文件头注释里，照着塞就行。

---

## 先手动验证一遍

别直接等第二天，先手动跑：

```bash
# 只生成 HTML，不发信
node tools/daily_mail.js --data data.json --out mail.html

# 用浏览器打开 mail.html，看看排版对不对
# 没问题再加 --send 真发一封给自己
node tools/daily_mail.js --data data.json --send
```

`--today 2026-10-28` 可以覆盖日期，用来预演「下周三会收到什么」。

---

## 邮件里有什么

四块，按需出现：

1. **已逾期**：逾期的任务（有逾期才出现，混在「未来 N 天」里最容易被跳过）
2. **DDL 倒计时**：N 天内要交的
3. **今日课表**：今天的课（这块随信必发，是邮件主体）
4. **今天该推进的长任务**：末尾还会单列「已落后计划」的阶段

当日课表**带周次过滤**——第 15 周不会再提醒你一门 1-14 周的课。

---

## 改配色的人必读

邮件的配色和页面是**两份色板**：

- 页面：`campus-workbench.html` 里的 `:root` 变量
- 邮件：`tools/daily_mail.js` 顶部的 `const C = {...}`（内联 style，硬编码）

改了页面不改脚本，**收到的邮件还是旧样式**——页面上看是新的，邮箱里是旧的。
这个坑很隐蔽，因为只有真发一封才看得出来。

改的时候两处一起改。邮件客户端限制多，只能照搬色值和方圆角口径，不能照搬 class 结构。

---

## 限制

**定时任务跑在你的电脑上，不是云端。**

- 关机 / 睡眠的时段不会发
- 醒过来后如果已过点，任务会**补发**（迟到但不丢）
- 要 7×24 准时，得让机器常开

判定逻辑是「今天已经发过就跳过」，所以不会一天发两封。
