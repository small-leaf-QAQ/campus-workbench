# 快速开始

三种用法，按你需要选一种。**A 不需要任何账号**，先花两分钟看看值不值得往下做。

---

## A. 打开就看（0 分钟，不需要账号）

1. 解压，找到 `index.html`
2. 双击

就这样。页面会直接进主界面，弹出一页使用说明，左上角写着「数据源：演示数据 · 仅本机」。

里面是示例数据：几门课、几个 DDL、一个拆成四步的课程设计、两条群消息。**随便点、随便改、随便删**，
反正只存在你这台电脑的浏览器里，清缓存或换设备就没了。

**适合**：给别人演示、自己先摸摸看、判断这个工具值不值得用。

> **如果双击打开是空白或一片登录墙**
> 说明你拿到的是"已经填过云配置"的版本（比如作者自己部署的那份）。
> 这种版本必须有网络和账号才能进。请改用仓库里这份 `index.html`，或者往下看 B / C。

> **Safari 用户**：macOS 上双击 `.html` 有时会用别的程序打开。右键 → 打开方式 → Safari。
> iPhone / iPad 上不能直接双击本地文件，需要先放到网上（见 B 或 C）。

---

## B. 本地起个服务（2 分钟）

比 A 多做一步，换来两件事：可以用手机/平板通过局域网访问，也避开了少数浏览器对 `file://` 的限制。

**需要**：电脑上有 Python 3 或 Node.js 之一。没有的话 A 完全够用。

### 用 Python

```bash
# 在本仓库目录下执行
python -m http.server 8000
```

### 用 Node.js

```bash
npx serve -l 8000
```

然后浏览器打开 <http://localhost:8000/>。

**手机访问**：让手机连同一个 Wi-Fi，在手机浏览器里打开 `http://你电脑的局域网IP:8000/`。
电脑 IP 用 `ipconfig`（Windows）或 `ifconfig`（macOS / Linux）查，形如 `192.168.1.7`。

**验收**：手机上能看到同样的界面，左上角仍是「演示数据」。

> **注意**：这种方式下每台设备的浏览器各存各的数据，互不相通。
> 想在手机和电脑之间同步，必须走 C。

## C. 接到自己的云数据库（20–40 分钟）

这一步之后才是"真正的应用"：手机验证码登录、数据跨设备同步、每人一份、AI 识别可用。

你需要准备：

| 需要 | 说明 |
|---|---|
| 一个 [WorkBuddy](https://www.workbuddy.cn) 账号 | 免费注册，用手机号 |
| 客户端（桌面端） | 建应用、跑建表脚本都在客户端里完成 |
| 20–40 分钟 | 主要时间花在建表和等发布 |

**完整步骤见 → [部署到云端](02-部署到云端.md)**

大致是五步：

1. 在 WorkBuddy 里新建一个工作目录，把 `campus-workbench.html` 放进去
2. 让它「发布成在线应用」，拿到域名和 publishableKey 两个值
3. 让它按 `deploy/schema.sql` 建五张表
4. 把两个值填进 HTML 的 `CLOUD_CFG`，重新发布
5. 打开域名 → 登录 → 加一条课程 → 刷新还在，就成功了

## 三种方式对比

| | A 双击 | B 本地服务 | C 云端 |
|---|---|---|---|
| 需要账号 | 否 | 否 | 是 |
| 需要联网 | 否 | 否 | 是 |
| 数据存哪 | 本浏览器 | 本浏览器 | 云数据库 |
| 跨设备同步 | 否 | 否 | 是 |
| 多人各自一份 | 否 | 否 | 是 |
| AI 识别课表/通知 | 否 | 否 | 是 |
| QQ 机器人 | 否 | 否 | 是 |
| 每日邮件 | 否 | 否 | 是（另需配置） |
